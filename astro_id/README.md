# astro_id: the engine

## Brief
The library behind the `astro-id` command. It plate-solves a night-sky photo with ASTAP, refits the whole frame, names what is in it (constellations, Messier/NGC/IC objects, named stars, Sun, Moon, planets), scores each name 0-100, measures frame quality and writes JSON, CSV and labeled copies.

- Commands (`cli.py`): `solve`, `label` (the simple one-step labeler), `moon`, `session`, `cull`, `check` (alias `doctor`), `site`, `setup`, and `facet ...` from [facet/](facet/README.md). Options: [REFERENCE](../docs/REFERENCE.md).
- `astro-id moon` (`moon.py`, catalog in `moon_catalog.py`) is separate from the plate solve: a Moon close-up has no stars, so it fits the disc and names maria, craters, ranges and Apollo sites. `moon_catalog.py` is generated by `tools/make_moon_catalog.py`; do not edit it by hand. Plan and limits: [the Moon plan](../docs/plans/2026-11-15-moon-features.md).
- `check` reports the minimum requirements (Python, uv, ASTAP and its database, optionally a Facet); the rules live in `requirements.py`.
- Depends on: ASTAP (external), astropy, numpy, Pillow and the rest of `pyproject.toml`. Used by: `facet/`, the `astro-id` command, `tests/`.
- Gotchas: reference data is downloaded, never vendored (licenses); a photo's own stars below the horizon at the camera time mean the clock is wrong, not the solve ([DETAILS](../docs/DETAILS.md)).

## Tests
- Covered by: `tests/test_*.py` (solve, identify, quality, cull, session, site, horizon time, small photos, labels, requirements, Moon).
- Run just the engine: `uv run pytest -q tests -k "not facet and not update"`; the Moon alone: `uv run pytest -q tests/test_moon.py`.
- Gaps: the only real-sky solve in CI is the example set (`tests/check_examples.py`, CI job `examples`); the Moon's NASA ephemeris checks skip without a cached DE421.
